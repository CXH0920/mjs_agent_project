## 一、产品定位与需求边界（讨论确认）

多模拟器支持的初衷：项目要分发给多人使用，每个人偏好使用的模拟器不同，工具需要跑通主流五品牌
（MuMu / 雷电 / 夜神 / 逍遥 / 蓝叠）。需求边界：

- 五个品牌**各自都能单独**连通并获取图像，在保证项目功能不出现问题的前提下执行后续功能即可；
- **不存在同时连接多台模拟器的场景**；品牌为单选模型，用户选定后基本不再切换；
- 由此明确不做（按"简洁优先"原则判定为过度设计）：每品牌独立配置档案、多会话并行连接等
  "设备隔离"类方案。连接正确性由画面自证（抓取图像即模拟器画面），风险收敛点在**显示诚实**。

## 二、问题清单（真机取证）

### P1 蓝叠国内版探测器完全失效（根因级）

- 现象：选"蓝叠"探测，日志报 `蓝叠注册表枚举失败：[WinError 2] 系统找不到指定的文件。`，
  结果永远为空，并连带触发 P3 的旧结果残留。
- 根因（真机取证）：
  1. 代码只找注册表键 `SOFTWARE\BlueStacks_nxt`（含 WOW6432Node、`BlueStacks_x`），
     而国内版实际键为 `BlueStacks_nxt_cn`（HKLM 与 HKCU 均存在）；
  2. 更根本：国内版 5.22.170.6509 注册表**没有 Guests 子键、无任何 BstAdbPort 值**，
     实例配置在 `<UserDefinedDir>\bluestacks.conf`
     （实测：`bst.instance.Pie64.adb_port="5555"`、`bst.instance.Pie64.status.adb_port="5555"`、
     `bst.enable_adb_access="1"`；UserDefinedDir 可从注册表值取得，本机指向数据目录而非安装目录）；
  3. 探测失败提示"请先在蓝叠 设置 → 高级 → ADB 中开启"是误导——本机 ADB 实际已开启
     （5555 正在监听，属 HD-Player.exe），只是探测器读不到端口。

### P2 雷电注册表探测键名不匹配（隐患级）

- 现象：`未找到雷电 console 工具（ldconsole），已回退端口段扫描`。
- 根因：`ldplayer.py` 注册表探测只找 `SOFTWARE\leidian\ldrun`，LDPlayer 9 实际写
  `SOFTWARE\leidian\ldplayer9`（值 InstallDir）。雷电自定义路径安装时找不到 ldconsole，
  无谓退化为端口扫描兜底。
- 本机叠加情况：雷电注册表残留但安装目录已删除（`G:\z_test\ld\leidian\LDPlayer9\` 不存在），
  本机必然走端口扫描，作为 P3/P5 的实测场景。

### P3 切换品牌后旧结果残留（显示语义）

- 现象：选雷电 → 端口扫描把蓝叠监听的 5555 标注为"雷电 9 实例 1（端口扫描）"；
  再选蓝叠 → 探测失败，列表仍显示这条雷电实例（即用户观察到的"选蓝叠探出雷电实例"）。
- 根因：
  1. 端口段扫描按"所选品牌"标注（既有设计取舍：蓝叠与雷电默认端口同为 5555，不猜品牌），
     UI 无"品牌未验证"提示；
  2. 探测失败时 UI 走"保留上次结果"策略——同品牌内是善意设计，**跨品牌切换时语义错误**
     （旧品牌结果对新品牌不适用），失败原因仅藏在实例状态 tooltip 中。

### P4 ADB 路径不随品牌切换（配置观感）

- 现象：无论品牌怎么切，ADB 路径永远显示旧值（MuMu 的 adb.exe）；当前 config.env 存在
  跨品牌混搭（路径=MuMu、端口=5555）。
- 根因：配置为全局单份 EMULATOR_ADB_PATH/PORT；切换品牌只更新品牌并刷新设备，不重探路径。
  adb 协议通用所以功能不受影响，但"固定写好"的观感造成配置不可控感。

## 三、需求

### R1 蓝叠国内版探测适配（必修，蓝叠为长期支持对象）

1. 注册表键补 `BlueStacks_nxt_cn`（HKLM/HKCU，含 WOW6432Node），与既有 `BlueStacks_nxt`
   逻辑并存兼容（国际版 Guests 契约保留）；
2. 注册表 Guests 读不到实例时，解析 bluestacks.conf：
   - 实例枚举：`bst.instance.<名>.adb_port` / `bst.instance.<名>.status.adb_port`
     （status 为当前实际端口，优先采用）；
   - 门控：`bst.enable_adb_access="0"` 时维持"请先在蓝叠设置中开启 ADB"的提示语义；
3. conf 定位顺序：注册表 UserDefinedDir / DataDir → ProgramData 常见路径兜底
   （覆盖国际版 `C:\ProgramData\BlueStacks_nxt\bluestacks.conf`）；
4. 失败提示修正：ADB 已开启但端口读不到时，不得提示"请先开启 ADB"。

### R2 雷电注册表键修正（必修）

`_probe_registry` 键列表补 `SOFTWARE\leidian\ldplayer9`（含 WOW6432Node），
使自定义路径安装的雷电能找回 ldconsole，减少无谓的端口扫描兜底。

### R3 品牌切换联动重探 ADB 路径（体验）

切换品牌时后台重探一次 ADB 路径：找到新品牌自带 adb 则更新；找不到则保留旧路径并照常
刷新设备列表（不弹模窗打断——adb 通用，旧路径仍可用）。

### R4 切换语义：旧品牌结果不带入（体验）

切换品牌 = 换探测上下文：清空上一品牌的设备列表，显示"探测中"；探测失败显性报
"未探测到 + 原因"，不再保留上一品牌的旧结果。**同品牌内**刷新失败保留原结果的既有策略
维持不变。

### R5 端口扫描候选"品牌未验证"标注（兜底防呆）

端口扫描兜底产出的候选实例，在行名或 tooltip 中标注"品牌未验证"
（5555 等雷电/蓝叠共用端口存在归属歧义），避免用户把候选误认为已确认归属。

### R6 品牌特性悬停提示（新增）

- 位置：「设备与连接」页模拟器品牌行右侧（品牌标签 + 下拉框同一行，见 2026-10-25 配置
  界面截图；代码锚点 `MumuDeviceSection` 品牌行，现网格第 2 行右侧有空位）；
- 形态：显眼的提示标识（如 ⓘ 图标），鼠标悬停显示说明文案；
- 内容：随所选品牌联动的**品牌特性提示**，文案随下拉框当前项切换。用户点名的两条：
  - 雷电：推荐使用稳定版雷电 9；
  - 蓝叠：使用前需先到蓝叠 设置 → 高级 中开启 ADB（Android 调试桥）；
  - MuMu / 夜神 / 逍遥：已按 2026-10-25 本机实测与官方资料定稿，见第五节。

## 四、验收标准

## 五、品牌特性调研结论与 R6 文案定稿（2026-10-25 实测）

> 调研方式：本机四品牌实测（蓝叠 5.22 中国版 / MuMu 12 / 夜神 7.0.6.2 / 逍遥 9.5.8.0，
> 雷电未安装以官方资料补齐），并现场复现了跨品牌 adb 互杀。证据级别逐条标注。

### 5.1 逐品牌连接注意点

| 品牌 | 默认 ADB | 默认端口 / 多开规律 | 关键坑（证据） |
| --- | --- | --- | --- |
| MuMu 12 | 默认开启，无需设置 | 16384；多开 +32（16416…） | MuMu 6 老版端口体系为 7555，勿混用；端口查右上角菜单→问题诊断，或 `nx_main\MuMuManager.exe info`（模拟器未启动也可读，实测）。adb server 关闭模拟器后仍常驻（实测，曾隔品牌连上蓝叠 5555） |
| 雷电 9 | 默认开启 | 5555；多开 +2（5557…） | 默认端口与蓝叠相同，两者同开时 `adb connect 127.0.0.1:5555` 静默连到先启动方，不报错（官方帮助＋MAA 端口规律）。推荐稳定版雷电 9；雷电 14 为 2026-04 新出的 Android 14 内核版本，与雷电 9 双内核并行，如需支持另立需求 |
| 夜神 | 默认开启 | 62001；多开跳 62025 后 +1（62026…） | 多开端口不规律，勿假设等差（官方 FAQ）；自带 nox_adb 1.0.36 极旧（本机实测），最易触发 5037 互杀；模拟器内 USB 调试仅兜底，非必须 |
| 逍遥 | 默认开启，无需设置 | 21503；多开 +10（21513…） | 本机 9.5.8.0 实测零配置连上；模拟器内 USB 调试 / 网络模式 NAT 仅兜底 |
| 蓝叠 5 | **默认关闭**，须 设置→高级→Android 调试桥 手动开启 | 端口以设置页显示为准（默认 5555） | 五家中唯一默认关 ADB（本机已开启，5555 监听中）；`adb devices` 中同时以 `emulator-5554` 与 `127.0.0.1:5555` 双序列号出现（实测，探测/匹配需去重）；自带 HD-Adb 协议 36 偏旧 |

### 5.2 通用结论（本机实测复现）

1. 5037 端口全局唯一一个 adb server，各品牌自带 adb 版本互异（蓝叠 36 / 夜神 1.0.36 /
   MuMu 41），混用即互杀断连——实测中蓝叠 adb 与 MuMu adb 两次互杀。工具链统一用一份
   platform-tools，不用品牌自带 adb。
2. 5555 为雷电/蓝叠共用端口，探测到 5555 不能反推品牌（与 R5"品牌未验证"标注呼应）；
   蓝叠双序列号问题同步纳入探测实现注意项。
3. 系统级前提：Hyper-V / 虚拟机平台 / Windows 虚拟机监控程序平台 / Windows 沙盒 /
   内核隔离（内存完整性）须全关（本机已确认处于该状态，五家要求一致）。

### 5.3 R6 定稿文案（待实施：MumuDeviceSection 品牌行 ⓘ 提示，随品牌联动）

- MuMu：默认开启 ADB；端口默认 16384（多开 +32 递增），可在模拟器右上角菜单 → 问题诊断 中查看。
- 雷电：推荐使用稳定版雷电 9；默认端口 5555（多开 +2 递增）。
- 夜神：默认开启 ADB；端口默认 62001，多开为 62025、62026…依次递增，可在夜神多开器中查看。
- 逍遥：默认开启 ADB；端口默认 21503（多开 +10 递增），可在逍遥多开器中查看。
- 蓝叠：使用前需在蓝叠 设置 → 高级 中开启 ADB（Android 调试桥）。
