# 官方 PC 客户端直连需求（只读图像源）

> 状态：需求共识已收拢，待实施；采集技术选型不在本档范围，另行整理技术设计文档。
> 来源：2026-10-25 三轮需求讨论收拢 + 两路事实侦查（公开资料检索 + 仓库实查）。
> 真机取证尚未进行（客户端尚未安装）：窗口特性等事实暂以公开资料为据，均标注"待真机验证"。

## 一、产品定位与需求边界

工具在模拟器连接之外新增「直连官方 PC 客户端」方式，只读取客户端窗口呈现的画面，
作为与模拟器并列的图像来源，供既有识别功能使用。需求边界：

- **单一图像源**：连接方式单选，同一时刻只连一个来源（官方 PC 客户端或某一模拟器），
  不存在并行连接场景；**不支持多开**，发现多个客户端窗口时由用户选择一个。
- **全程只读**：只读取窗口呈现画面，不向客户端或操作系统发送任何输入（红线详见第六节）。
- **下游复用**：既有只读识别功能（官方榜单导入、选将识别、对局攻略、巅峰整板等）
  通过共享管线直接获得 PC 端图像，最多做兼容性适配，不为 PC 端新做特化功能。
- **使用范围**：按面向分发用户的标准设计兼容；当前实际用户仅开发者本人，
  配置界面允许整体改造，唯一约束是不产生重大歧义。
- **显示诚实**：连接正确性由画面自证（抓取图像即客户端画面），风险收敛点在提示与显示——
  异常必须给出人话引导，不允许静默降质或误导性文案。

## 二、客户端事实（需求依据）

1. 官方提供 Windows 原生 PC 客户端（官网直装 / Steam / WeGame / Microsoft Store / TapTap
   多渠道）；**第一适配对象为官网直装版**（无平台包装层，窗口特征最直接）。
2. 客户端默认**独占全屏**；可切窗口化 / 无边框窗口（游戏内设置或 Alt+Enter）；
   分辨率为固定 16:9 档位（720p / 900p / 1080p / 1440p）——社区资料，**待真机验证**。
3. **独占全屏下系统级截图为黑帧**（玩家社区大量证实，非工具缺陷）；窗口化后截图正常。
   工具绝不代切窗口模式（属于向系统发送模拟输入，踩红线）。
4. 官方榜单为官方内部数据汇总的胜率 / 出场 / 禁用统计，**与登录载体无关、全局一份**
   （讨论确认）——PC 端截图可直接进入现有榜单导入口径，无"平台分池"问题。
5. 未发现内核级反作弊的公开资料；仅有加壳保护与杀毒软件误报的官方 FAQ。
   只读截屏在公开资料层面无阻断或处罚报告。
6. 本机未安装客户端，实施前需先安装并完成第四节真机取证。

## 三、需求条目

### R1 连接方式扩展（发现与选择）

1. 「连接方式」新增「官方 PC 客户端」选项，与五个模拟器品牌并列单选。
2. 选中后自动发现客户端窗口，三态语义：
   - 未运行 → 候选列表为空，提示"未检测到名将杀客户端窗口，请先启动客户端"；
   - 恰好一个 → 自动选定；
   - 多个 → 列出让用户选择一个（不支持多开）。
3. 窗口识别依据（窗口标题 / 进程特征）以第四节真机取证记录为准，不凭空猜测。

### R2 画面采集（只读）

1. 只读取客户端窗口呈现画面；不得有任何向客户端或操作系统发送输入的行为（第六节红线）。
2. **窗口化前提**：客户端处于窗口化 / 无边框模式时方可有效采集；独占全屏下采集结果为
   黑帧，必须检测并按 R4 引导用户切换，工具不代切。
3. **遮挡与最小化**：窗口被其他窗口遮挡时应可正常采集（待真机验证）；
   最小化时无法获得有效画面，按 R4 报错。
4. 采集手段应在用户无感的前提下自动选择可用方式，无需用户配置；
   具体技术选型与降级链另行成文。

### R3 配置界面改造

1. 「设备与连接」页适配双形态。选中「官方 PC 客户端」时：
   - 设备下拉 = 客户端窗口候选列表，刷新按钮 = 重新枚举窗口；
   - 展示进程名、窗口标题与客户区分辨率；
   - **ADB 相关区块整体隐藏**（ADB 路径输入框、自动探测按钮、端口字段）。
2. 显示诚实：PC 方式下界面不残留任何 ADB 字样；模拟器方式下不出现窗口语义混排。
3. ⓘ 悬停提示（随连接方式联动）：PC 项说明"仅支持窗口化模式，
   请在游戏内设置或按 Alt+Enter 切换；工具不会代为切换"。

### R4 异常场景行为

| 场景 | 行为 |
|---|---|
| 客户端未启动 | 候选列表空 + 提示"未检测到名将杀客户端窗口，请先启动客户端" |
| 独占全屏（黑帧） | 采集自检与每次采集均校验，报"检测到全屏黑屏，请将客户端切换为窗口化（游戏内设置或 Alt+Enter）；若已处于窗口化，请确认游戏画面已完全加载" |
| 窗口最小化 | 报"请还原客户端窗口后再采集" |
| 窗口被遮挡 | 正常采集不报错（待真机验证确认） |
| 多个客户端窗口 | 列表选择一个，明确不支持多开 |
| 720p / 900p 档位 | 放行 + 非阻断提示"低分辨率可能影响识别准确率" |

### R5 分辨率档位策略

1. 16:9 全档位放行：识别管线按参考分辨率等比自适应，各档位均可尝试。
2. 720p / 900p 放行同时给非阻断提示。依据：识别管线存在低分辨率静默降级路径
   （卡位检测使用绝对像素阈值判定行间隙），低档位有踩线可能，不允许静默降质而不告知。

### R6 下游功能复用与兼容验证

1. 官方榜单导入对话框**零改动**（其为磁盘文件导入流，与截图来源天然解耦）。
2. 各页截图按钮、自动轮询、巅峰整板监听在 PC 源下等价可用，行为语义与模拟器一致。
3. 与模拟器链路的**结果一致性**作为验收口径：同一榜单页面两端分别走完导入，
   识别结果应一致（数据口径一致性，不涉及渲染差异——渲染差异只影响识别准确率，
   列入第四节取证）。

### R7 文档与声明

1. README / 工具说明加入用途声明："截图数据仅供个人学习研究使用"。
2. 用户引导文档写明窗口化前提与切换方法（游戏内设置或 Alt+Enter）。

## 四、真机取证清单（实施前置，一次性完成）

客户端安装（官网直装版，记录版本号）后逐项取证并记录结论：

1. 窗口化 1080p 下系统级截屏出图质量（不黑屏、文字清晰可 OCR）；
2. 独占全屏黑帧取证（确认黑帧现象与检测可行性）；
3. 窗口最小化时的帧表现；
4. 窗口被遮挡时的采集可用性；
5. **窗口标题 / 进程名 / 窗口类名记录**（R1 窗口识别规则的定稿依据）；
6. 榜单页 PC 端与模拟器端渲染差异对比（字体渲染、UI 缩放、配色——OCR 准确率视角）；
7. 150% DPI 缩放下截图坐标正确性与文字清晰度；
8. 实际支持分辨率档位核实（16:9 档位清单为社区资料）。

## 五、验收标准

1. 自动化用例全绿：连接方式切换语义、窗口候选三态、黑帧判定、异常提示文案
   （扩展现有品牌探测与连接用例惯例）；
2. 真机验收：窗口化 1080p 下完整跑通官方榜单导入（截图 → 存盘 → 导入 → 识别 → 结果），
   与模拟器链路结果一致；
3. R4 异常场景六条各按预期行为复核；
4. 第四节真机取证清单完成并记录结论；
5. 红线复核（第六节）逐条通过。

## 六、红线复核（法律边界）

1. 全部改动限于发现 / 采集 / 提示 / 显示；不新增任何自动操作、输入注入、进程注入、
   内存读取、hook、反作弊干扰功能；
2. 新增采集模块须以与现有采集模块同格式在 docstring 声明法律红线；
3. 抓取数据不入版本库，经私有数据仓同步并登记来源（data/SOURCES.md）；
   PC 端截图与识别数据同样适用；
4. 工具说明含"仅供个人学习研究"用途声明。

## 七、明确不做

- 多开 / 多源并行连接；
- 代发任何输入（含代切窗口化、代翻页）；
- PC 端特化识别功能；
- Windows 7 / 8 兼容承诺（理论可行但测试不承诺）；
- 720p / 900p 识别质量承诺（放行但明示风险）。
