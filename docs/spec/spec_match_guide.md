# 对局攻略页面（首版）需求规格

> 状态：已实现（首版）
>
> 范围：单将攻略聚合、手动阵营确认、敌方威胁提示
> 不包含：AI 实时分析、武将相性、组合胜率和真实对局胜率

## 一、目标与成功标准

### 1.1 目标

将现有“识别四名武将后展示头像和单将胜率”的页面，升级为可在 2v2 对局开始前快速使用的攻略工作台。用户应能在确认敌我阵营后，快速获取本方操作重点、敌方威胁和对抗建议。

### 1.2 成功标准

- 用户导入或识别四名武将后，可在 15 秒内完成阵营确认。
- 完成确认后，默认页在不访问网络、不调用 AI 的前提下，展示可执行的对局摘要。
- 任一已识别武将缺少攻略或胜率数据时，页面保持可用，并明确显示“暂无数据”。
- 页面不把单将胜率描述为阵容或对局胜率，不基于空的相性数据产出配合结论。

## 二、现状、前置假设与数据边界

### 2.1 当前可用数据

| 数据源 | 已有内容 | 首版用途 |
|---|---|---|
| `Hero` | 名称、势力、定位、血量、手牌上限、技能 | 阵容卡片、技能速览 |
| `HeroGuide` | 核心要点、新手提示、优势/劣势类型、对抗建议、Markdown 正文 | 本方打法、敌方威胁、完整攻略 |
| `2v2胜率排行.csv` | 160 名武将的历史单将胜率 | 单将强度参考 |
| OCR 结果 | 武将名、槽位顺序、识别置信度、楚/汉军标签 | 填充阵容、自动区分敌我后保留人工确认 |

### 2.2 已知限制

- 第 5 个候选位置固定为玩家本人，第 1、2 个位置为敌方，第 3、4 个位置中唯一识别到名称者为队友；席位规则负责自动分配敌我。OCR 读取每张角色卡右上角的【楚军】/【汉军】标签，仅用于校验席位结果，标签缺失或识别失败不阻断自动分配。席位关系不符合规则时保留手动确认。
- 当前 `synergies.json` 无相性记录，所有 `HeroGuide.synergizes_with` 均为空；首版禁止显示“我方配合评分”或“推荐搭档”。
- `Hero.mode_viability["2v2"]` 尚无数据；首版不显示 2v2 强度梯队。
- 胜率为单将榜单数据，可能缺失或过期，不能用于计算或暗示“我方胜率”。
- 攻略正文虽包含开局/中局/残局章节，但首版只提取结构化字段做摘要；完整正文通过现有 Markdown 阅读弹窗查看。

### 2.3 设计原则

1. **先确认，再建议**：未指定敌我时，不生成阵容级建议。
2. **离线、秒开、可解释**：摘要由固定规则拼装；每条建议能追溯到对应武将攻略字段。
3. **不伪造数据完整度**：缺失数据显式降级，不用泛化文案补齐。
4. **临场优先**：默认展示最多 3 条行动项，完整长文按需展开。

## 三、用户与核心流程

### 3.1 目标用户

正在进行或即将开始 2v2 对局的玩家。用户已经获得游戏截图，或已连接模拟器；其首要需求是快速确认阵容并决定开局策略。

### 3.2 主流程

```text
进入对局攻略页
  → 识别当前阵容 / 从图片导入
  → 审核识别结果（必要时替换武将）
  → 指定两名我方与两名敌方
  → 点击“确认阵容并生成攻略”
  → 生成离线摘要并默认打开“总览”
  → 查看我方打法、敌方威胁或单将完整攻略
```

### 3.3 异常流程

| 情况 | 页面行为 |
|---|---|
| 未识别到武将 | 保持空状态，提示重新识别或从图片导入 |
| 仅识别 1～3 名 | 展示已识别卡片；禁用“生成对局摘要”，提示补齐 4 名 |
| 重复识别到同一武将 | 标记该卡片“待确认”，不阻止用户手动替换 |
| 武将不存在于本地库 | 显示 OCR 原名和“本地无此武将”；不允许计入确认阵容 |
| 缺攻略 / 缺胜率 | 卡片与分析区分别显示“暂无攻略 / 暂无单将胜率”，其他内容正常展示 |
| 未完成敌我确认 | 右侧显示确认引导及单将速览，不显示行动优先级 |

## 四、界面与交互需求

### 4.1 总体布局

保持主窗口 1100×760px 的既有尺寸与天蓝色主题；页面采用顶部操作栏、左侧阵容区、右侧攻略区。

```text
标题与识别状态                                              识别 / 导入 / 更多
┌────────────────────────────────┬────────────────────────────────────┐
│ 阵容与阵营（42%）               │ 临场攻略（58%）                     │
│ [确认阵容并生成攻略]             │ [总览] [我方打法] [对抗敌方] [详情] │
│ 我方阵容：我 / 队友              │ 行动卡、风险卡、我方速览卡           │
│ 敌方阵容：敌方 1 / 敌方 2        │                                    │
│ 待确认：未分配角色               │                                    │
└────────────────────────────────┴────────────────────────────────────┘
```

- 左侧卡片采用紧凑 2×2 布局，头像为 80×108px，默认 42% 宽度下不出现横向滚动；窄屏仅保留纵向滚动。
- 卡片按当前敌我归属重排为“我方阵容 / 敌方阵容 / 待确认”，不按 OCR 槽位顺序混排。
- 复用现有势力色、头像加载、双击打开 `HeroSkillDialog` 和“完整攻略”按钮打开 `GuideDetailDialog`，不重复实现。

### 4.2 顶部操作栏

| 元素 | 要求 |
|---|---|
| 标题 | 固定显示“对局攻略” |
| 识别状态 | 展示最近识别时间、有效武将数、待确认数；不以 OCR 置信度代替攻略可信度 |
| 识别当前阵容 | 复用 `match_guide` 模板和强制 OCR 流程 |
| 从图片导入 | 复用本地图片导入和 OCR 流程 |
| 更多操作 | 收纳“保存截图”和“清空阵容”；保存截图不触发分析更新，清空阵容只清除页面会话状态 |

空状态提供“识别当前阵容”和“从图片导入”两个直接入口，按钮位置与字体风格和选将推荐空状态保持一致。

### 4.3 阵容区

阵容区固定四个槽位，按“我方 2 名 + 敌方 2 名”展示。识别后按固定候选席位自动分配：候选 1、2 为敌方，候选 5 为玩家本人，候选 3、4 中唯一识别到名称者为队友；楚军/汉军标签只用于校验，缺失时仍可自动分配，用户始终可以手动确认或调整。

每张卡片必须展示：

- 头像、武将名、势力标签、定位、单将胜率（如有）。
- 识别状态：已确认、待确认、本地无数据三态。
- 阵营归属控件：有明确选中态的 `我方`、`敌方`、`未定` 三段控件；已分配的两个同阵营角色分别标为“我/队友”或“敌方 1/敌方 2”。
- `替换武将`入口：打开已有单选武将选择能力，替换仅影响当前页面内存状态。
- 双击头像：打开既有技能详情弹窗。

确认规则：

- 仅当本地可识别的 4 名不同武将，且我方、敌方各恰好 2 人时，阵容为“已确认”。
- 用户切换卡片阵营后，若同阵营已满 2 人，阻止操作并提示先取消其中一人。
- “我”标识默认分配给首个被设为我方的武将，用户可在两名我方中切换；此操作不改变攻略规则，只用于视觉定位。
- 即使 OCR 已识别出两名我方和两名敌方，也必须由用户点击“确认阵容并生成攻略”后才生成摘要；之后改动任一阵营或替换武将，须重新确认。

### 4.4 攻略区标签页

#### 总览（默认）

已确认阵容时按以下顺序显示：

1. **数据提示条**：如攻略、胜率缺失，显示中性提示；默认折叠，点击可查看缺失项目。
2. **本局行动优先级**：最多 3 张行动卡，格式为“动作 + 对象 + 原因”，带编号与蓝色强调。
3. **敌方威胁**：在红色风险卡中展示每名敌方最多 2 条要点。
4. **我方速览**：在蓝色信息卡中展示两名我方各 1 条核心要点与 1 条新手提示。

未确认阵容时显示：确认步骤、已识别单将速览和“确认后生成对局摘要”说明。

#### 我方打法

按我方两名武将分两张卡展示：核心要点（最多 3 条）、新手提示、完整攻略按钮。不得展示“配合评分”“推荐搭档”或推断性的联动结论。

每张攻略卡占满内容区宽度；核心要点、新手提示及长武将名称必须自动换行，不得截断或触发横向滚动。

#### 对抗敌方

每名敌方一张威胁卡，展示：

- 该武将的 1～3 条核心要点。
- 其攻略中的“被谁克制”类型。
- 面对该武将的 `counter_strategy`。
- 完整攻略按钮。

每张威胁卡占满内容区宽度；所有长文本自动换行，不得截断或触发横向滚动。

#### 单将详情

按四名武将展示基础信息与完整攻略入口。复用现有 Markdown 弹窗；正文不在页面内同时展开。

### 4.5 视觉规则

- 蓝色用于我方及可执行操作，橙/红色用于敌方状态、威胁和风险，灰色用于未确认或缺失数据。
- 势力色仅表达势力，不能用于表达强弱或敌我。
- 结论标题 18px；行动标题 14px 加粗；正文 12～13px。
- 行动项使用编号和动词开头，例如“1. 优先压制：敌方 X……”。

## 五、规则化摘要需求

### 5.1 输入

`MatchAnalysisService` 接收已确认的我方两名、敌方两名，以及只读的 `Hero`、`HeroGuide`、单将胜率数据。

### 5.2 输出

服务输出仅供 UI 渲染的只读对象：

```python
MatchAnalysis(
    allies: list[HeroSummary],
    enemies: list[HeroSummary],
    priorities: list[ActionItem],
    threats: list[ThreatItem],
    ally_tips: list[GuideTip],
    missing_data: list[str],
)
```

每个 `ActionItem` 和 `ThreatItem` 必须携带来源字段（例如 `counter_strategy` 或 `key_points[0]`），用于测试与后续“查看来源”功能。

### 5.3 首版生成规则

- 对每名敌方：优先取其 `counter_strategy` 生成“应对”项；为空时不生成替代结论。
- 对每名敌方：取最多 2 条 `key_points` 作为“威胁”，保留原意，不改写成必胜/必败判断。
- 对每名我方：取第 1 条 `key_points` 和 `tips_for_beginners` 生成速览。
- 行动优先级最多 3 条：先放敌方 `counter_strategy`，按敌方单将胜率从高到低排序；胜率缺失的角色排在已有胜率后，并保留其建议。
- 不计算综合分、不生成集火概率、不使用空相性数据；标题使用“优先应对”而非“必定集火”。
- 单将胜率旁必须注明“历史单将胜率”，且不参与任何面向用户的阵容胜率计算。

## 六、数据、架构与状态要求

### 6.1 状态边界

- 当前阵容、槽位、阵营和“我”标识只保存在 `LineupState` 的会话内存中；应用重启后清空。
- 不写入 `heroes.json`、`guides.json`、`synergies.json` 或 CSV。
- 每次 OCR 导入都必须替换上一次阵容；空识别结果也要清除旧阵容，防止新画面沿用旧阵营关系或旧摘要。

### 6.2 模块职责

| 模块 | 职责 |
|---|---|
| `MatchGuidePanel` | 连接截图/OCR 信号、卡片交互、发射配置请求；不直接保存阵容状态 |
| `LineupState` | 四个槽位的原始识别名、置信度、匹配武将、敌我、主将和显式确认；提供可分析性及失败原因 |
| `MatchAnalysisView` | 只渲染确认前提示或 `MatchAnalysis` 的四个攻略页；不修改阵容状态 |
| `MatchAnalysisService`（新增） | 读取数据并生成可解释的对局摘要；不得引用 QWidget |
| `HeroManager` / `GuideManager` | 提供武将和攻略查询 |
| `win_rate_repository` | 提供只读单将胜率快照 |
| `MainWindow` | 继续编排 OCR 轮询与页面刷新，不包含摘要规则 |

服务不得持有 UI 引用；若未来生成任务异步化，仍通过 Qt Signal 回到 GUI 线程更新页面。

### 6.3 性能与容错

- 确认阵容后的摘要生成目标为 UI 线程内 100ms 以内完成；不得进行网络请求、文件写入或 AI 调用。
- 同次摘要生成中胜率数据只读取一次，不得逐卡重复读盘。
- 任何缺失或损坏的攻略记录均按单项缺失处理，不得使整个页面失败。

## 七、验收标准

### 7.1 功能验收

- 导入完整四人阵容后，四张卡均显示武将基础信息和正确的单将胜率或缺失状态。
- 未完成 2v2 敌我分配时，页面不显示行动优先级与阵容级结论。
- 为两名我方、两名敌方完成确认后，默认打开总览并展示不超过 3 条优先应对项。
- 敌方攻略存在 `counter_strategy` 时，该内容能在总览及“对抗敌方”中找到。
- 缺少一位敌方攻略时，其余三位的内容仍正常显示，并出现明确的缺失提示。
- 重新 OCR 或手动清空阵容后，旧阵营关系和旧摘要不会残留。
- 双击头像、完整攻略按钮、模拟器配置请求、截图导入等既有交互保持可用。

### 7.2 文案与数据验收

- UI 中不得出现“我方胜率”“阵容胜率”“最优搭档”“相性评级”等暗示当前未具备的数据。
- 胜率显示必须带“历史单将胜率”或同等说明；有数值时按百分比展示并带 `%`。
- 每条摘要建议均能在相应 `HeroGuide` 的结构化字段中找到依据。

### 7.3 建议测试覆盖

- `MatchAnalysisService`：完整数据、无攻略、无胜率、两名敌方胜率排序、无 `counter_strategy`。
- `LineupState`：未确认状态、明确失败原因、阵营人数上限、OCR 后（含空结果）状态重置、手动替换。
- `MatchAnalysisView` / `MatchGuidePanel`：确认前提示、确认后四个攻略页，以及重复识别和本地缺失状态的卡片渲染。
- 回归：现有图片导入、ADB 截图、头像双击技能、势力颜色刷新。

## 八、非目标与后续迭代

首版明确不做：

- 通过 AI 实时生成本局结论或复盘。
- 自动识别敌我阵营、玩家本人、座次或回合进度。
- 基于单将胜率推算阵容胜率。
- 相性评分、搭配推荐、组合历史战绩。

后续在 `synergies.json` 有可信数据后，可增加“我方配合”区，但需同时满足：相性数据存在、文案区分“相性评分”与“实战胜率”、缺失时不降级为猜测。若未来获得组合对局数据，再单独设计组合胜率和对位分析，不能复用单将榜单替代。
