# UI 设计系统规范

> 适用范围：`src/ui/` 下的 PySide6 页面、弹窗和共享控件。
> 本规范约束视觉基础、公共组件与已迁移页面；阶段三已完成应用外壳，阶段四已完成资料库两个二级视图的信息层级改造。

## 一、设计目标

界面采用“专业策略工作台 + 轻量游戏语义”的方向。应用框架保持安静、紧凑和可扫描；武将头像、势力色、敌我色及排名色只承担业务含义，不作为装饰性主题色。

设计必须满足以下原则：

1. 高频任务优先，识别、导入和确认等主操作在当前上下文内直接可见。
2. 同类组件拥有一致的尺寸、状态和语义，页面不得自行创造新的按钮颜色体系。
3. 颜色不是状态的唯一表达方式，必须同时提供文字、图标或形状差异。
4. 保持现有业务信号、数据读写和快捷键行为，不以视觉改造为由改变业务规则。
5. 最小支持窗口为 960×640px，默认窗口为 1100×760px，并验证 1440×900px。

## 二、基础 Token

### 2.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `CANVAS` | `#f4f6f8` | 应用和页面背景 |
| `SURFACE` | `#ffffff` | 输入、菜单和必要内容表面 |
| `SUBTLE_SURFACE` | `#edf1f5` | 次级选中、分组和弱提示 |
| `TEXT_PRIMARY` | `#1f2933` | 标题和正文 |
| `MUTED_TEXT` | `#66717e` | 辅助信息、时间和说明 |
| `BORDER` | `#d7dee7` | 常规分隔和控件边界 |
| `PRIMARY` | `#2f6ea5` | 主要操作、我方和焦点 |
| `SUCCESS` | `#26734d` | 成功、已连接和生效中 |
| `WARNING` | `#a15c00` | 待核实、过期和注意 |
| `DANGER` | `#b23a3a` | 删除、失败和敌方风险 |

势力色只能表达势力归属；蓝色用于主操作或我方，红色用于危险操作或敌方，金银铜色只用于推荐排名。动态势力色允许在组件内计算，其余颜色应来自 `src.ui.shared.style`。

### 2.2 字体

- 字体族：`Microsoft YaHei UI`，回退到 `Microsoft YaHei`、`SimHei` 和系统无衬线字体。
- 页面标题：20px，600/粗体。
- 区块标题：16px，600/粗体。
- 控件与正文：13px。
- 辅助文本：12px。
- 极小数据标签：11px，仅用于非关键元数据。
- 字号不随窗口宽度缩放；长文本通过换行和布局重排解决。

### 2.3 几何

- 基础间距序列：4、8、12、16、24px。
- 控件高度：紧凑 28px，默认 32px，主要操作 36px。
- 圆角：小控件 4px，内容表面 6px；不使用大圆角胶囊作为普通按钮。
- 页面内边距：16px；紧凑内容区可使用 12px。
- 图标：默认 16px，空状态图标 24px；图标按钮必须提供 Tooltip 和 AccessibleName。

## 三、组件语义

Qt 控件通过动态属性应用语义样式：

| 控件 | 属性 | 可选值 |
|---|---|---|
| `QPushButton` / `QToolButton` | `uiRole` | `primary`、`secondary`、`ghost`、`danger` |
| `QLabel` 状态标签 | `tone` | `neutral`、`info`、`success`、`warning`、`danger` |
| `QFrame` 通知条 | `tone` | `info`、`success`、`warning`、`danger` |

共享组件职责：

- `PageHeader`：页面标题、辅助状态和页面级操作。
- `EmptyState`：无数据或未执行状态，可包含一组主次操作。
- `StatusBadge`：短状态文本，不承担点击行为。
- `NoticeBanner`：需要用户注意的页内消息，不替代错误对话框。
- `DialogFooter`：统一的取消/确认操作区，确认按钮位于右侧。

业务页面只负责设置内容和语义，不复制这些组件的颜色、边框和间距。

### 3.1 资料库内容层级

- 主从页面的左侧检索栏宽度限制为 240–360px，结果计数紧邻筛选区，右侧内容占据剩余空间。
- 武将资料在右侧顶部保留当前武将身份头部；身份、内容切换、正文区块和局部操作按从上到下的层级排列。
- 同一内容上下文只保留一个直接“编辑”操作；删除等危险低频操作收纳到相邻“更多”菜单，并保留文字、危险语义和二次确认。
- 卡牌官方资料使用单一基础表面，内部用标题、摘要、简述和规则详解建立层级，不用嵌套卡片重复描边。
- 卡牌版本状态必须同时提供文字、色彩与左侧强调线：`active` / “生效中”使用成功色，`pending` / “待核实”使用警示色，`expired` / “已失效”使用中性灰。
- 资料详情只允许纵向滚动；960×640、1100×760、1440×900 三档均禁止页面级和详情区横向滚动。

## 四、交互状态

所有可操作控件必须具备默认、悬停、按下、聚焦和禁用状态。异步操作还应具备处理中状态：禁用重复提交，保持当前进度或状态文字，不通过无限弹窗反馈过程。

| 场景 | 表达方式 |
|---|---|
| 空数据 | `EmptyState`，说明原因并提供下一步操作 |
| 加载中 | 原位置状态文字或进度条，保持布局尺寸稳定 |
| 非阻断成功 | 页面状态或 Toast |
| 可恢复错误 | `NoticeBanner` 或字段级错误，保留用户草稿 |
| 阻断错误 | 模态错误对话框，说明原因和恢复方式 |
| 危险操作 | `danger` 按钮，并保留二次确认 |

## 五、窗口与响应规则

| 窗口 | 目标 |
|---|---|
| 960×640 | 核心任务可完成；只允许纵向滚动，不允许页面级横向滚动 |
| 1100×760 | 默认密度和基准布局 |
| 1440×900 | 内容扩大但不拉伸固定格式卡片，使用合理最大宽度或伸缩列 |

固定格式元素必须设置稳定尺寸或网格约束。工具栏在空间不足时优先收纳低频操作，不能压缩文字到不可读，也不能让按钮覆盖标题。

## 六、视觉基线与验收

改造前截图位于 `docs/ui_baseline/`，命名格式为：

```text
before-<宽>x<高>-<视图>.png
```

当前包含 `library-heroes`、`library-cards`、`recommendation-empty` 和 `match-empty` 四个视图，每个视图覆盖三档窗口尺寸。`before-` 是改造前基线，`after-foundation-` 是阶段二基础样式对照，`after-shell-` 是阶段三应用外壳对照，`after-library-` 是阶段四资料库内容层级对照。离屏环境缺少中文字体时可能显示方框，该基线仍用于检查几何、层级、溢出和布局稳定性，不用于字体渲染质量判定。

每阶段验收至少检查：

- 页面和弹窗无重叠、截断及非必要横向滚动。
- 主要操作在同一操作组中保持唯一最高权重。
- 状态颜色与文字语义一致，且不只依赖颜色。
- Tab、按钮、输入框和列表可通过键盘聚焦。
- 动态内容更新不会改变固定卡片和工具栏的整体尺寸。
- 所有文本文件保持 UTF-8、LF、无 BOM。
